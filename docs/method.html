Method & data

What each metric on this site means, where the data comes from, and how far to trust it.

Data

  • Corpus: … Private repositories are anonymized; only counts, sizes, models and dollars are published.
  • Verdict coverage: …
  • Scans per model: …
  • Full scans vs samples. Overview, Compare, Pick a provider and Pick effort use full scans. The benchmark and chunk-size curves on Pick a model come from code-scan init, which reviews a small code sample (one repository per benchmark), so they generalise less than full scans.
  • One run per configuration. No configuration was repeated, so run-to-run noise is not measured: treat small gaps (a few findings, a few cents) as possibly noise.

Metrics

Choose on recall, findings and cost; this data can't separate configurations on precision. Most scans have 0–3 false positives, so a precision gap of a few points is usually 1–3 findings, and those counts come from lenient agent triage (see Auto-triage), so real false positives are probably more.

  • Findings: every issue a scan reported, critical to low. Each scan counts its own; see Same bug for matching across scans.
  • Same bug: two findings from different scans in the same file with similar titles, or on nearby lines with somewhat similar titles. Matching is automatic, so some duplicates slip through and some distinct bugs merge.
  • Real (also called confirmed): triage judged the finding a real bug, including ones marked won't fix or already fixed by hand.
  • Precision: real ÷ (real + false positives). Other verdicts are left out (see Verdict coverage).
  • Recall: of all real issues found by any of the runs being compared (full scans of the same code), the share this run found. Only issues triaged real count; untriaged findings are ignored, so a run whose findings were not triaged can score low. Bugs no run found are not counted, so recall overstates real coverage. Recall is severity-weighted: critical 4, high 3, medium 2, low 1, using the highest severity any reviewer gave, so an issue weighs the same whichever run found it.
    Used on Pick a provider, Pick a model and Pick effort; the sample-based scores on Pick a model are called quality instead.
  • Unique findings: issues no other scan of the same repository found, counted only on files every one of those scans reviewed. "Unique confirmed" is the subset that is real.
  • Price: list price at scan time of every token of every reviewer agent (preamble, coordination, re-reads), not just the code. Cached input is priced at each provider's cache-read rate; Anthropic cache writes at 1.25× input.
  • $/100KB: scan price ÷ KB of source reviewed × 100. Chunk size (Pick a model): KB of source given to one reviewer agent at a time.
  • Wall clock: elapsed time while at least one reviewer was working, up to 10 reviewers in parallel by default. The parallelism limit each scan used is not recorded, so a faster wall clock may just mean more parallel reviewers. Pauses and the planner are excluded. Agent-minutes add up every reviewer's time instead.
  • Effort: Codex scans without an effort used the Codex CLI default, high; Claude scans used Claude Code's default, which is not recorded. Both are labelled "default" on other pages, but the triage table below merges Codex default into high.

Auto-triage

An agent re-reads each finding against the code and marks it real, false positive, won't fix or unsure, and may correct its severity.

  • Only Codex gpt-6.1-sol was measured as a triage agent (plus a few findings whose triage model was not recorded); there is no data on Claude triage cost or strictness.
  • Codex often also produced the findings it judged, so read "real" as agreement, not ground truth.
  • Triage often corrects severity, so don't filter scan output by the reviewer's severity before triage. The "model not recorded" row covers only a few dozen findings, so its percentages are not shown.
  • "Per agent" is how many findings one triage agent checked at once. Rows triaged different findings, partly in different repositories, so their $/finding is not a like-for-like test of group size or effort.
  • "Real" includes won't fix, as defined above. Severity changes count both directions.
