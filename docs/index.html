code-scan

Repository-wide bug scanning with parallel reviewer agents from Claude Code, Codex, Gemini, Antigravity, Copilot, Cursor or OpenCode. These pages show how reviewer models performed on real repositories and which to pick. Only Claude and Codex models have been benchmarked so far.

What do you want to decide?

OpenAI or Anthropic?Codex vs Claude on the same code: share of issues found, price, precision. Which model?Opus, Fable, Sonnet, Haiku and Codex by language, the known-bug benchmark and chunk size. Which effort level?Codex low → ultra and Opus low → max on one repository: what more effort buys and where it stops paying. Compare everythingEvery full scan as a sortable row with price, findings, false positives and time; plot any two measures.

Find your setup

Pick the language of the code you scan and what matters most to you: price, number of findings, findings per dollar or speed. The card's figures come from one effort study on TypeScript + Rust; the evidence below it shows what was compared on your language.

Install

# Claude Code
/plugin marketplace add dk-code-factory/code-scan
/plugin install code-scan@code-scan

# Codex CLI
codex plugin marketplace add dk-code-factory/code-scan
codex plugin add code-scan@code-scan

# Any Agent Skills host
git clone https://github.com/dk-code-factory/code-scan && node code-scan/bin/code-scan.js install

Then either use the setup from the card above, or run /code-scan:init in your repository to benchmark Claude models on a sample of your own code and pick one there. The card's CLI commands need no init and use a fixed 40KB chunk; only /code-scan:scan or /code-scan:init calibrates the chunk size for a Claude model.
