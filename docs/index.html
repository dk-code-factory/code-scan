Install

# Claude Code
/plugin marketplace add dk-code-factory/code-scan
/plugin install code-scan@code-scan

# Codex CLI
codex plugin marketplace add dk-code-factory/code-scan
codex plugin add code-scan@code-scan

# Any Agent Skills host
git clone https://github.com/dk-code-factory/code-scan && node code-scan/bin/code-scan.js install

Then run /code-scan:init once per repository: it benchmarks models on a sample of that repo and picks a chunk size for each.

How to pick a model

Default for full scans: Codex gpt-6.1-sol.

On every repository where it ran next to a Claude model on the same code it found the largest severity-weighted share of issues (gocql 0.76 vs Fable 0.43; seastar 0.81 vs Opus 0.30; scylla-rust-driver 0.59 vs Fable 0.55), at $0.27–0.52 per 100KB — about a seventh of Fable's price on the same 2.7MB of Rust. Its findings held up in triage (≥ 0.99 confirmed), but that triage was also done by Codex, so treat that figure as an upper bound.

Best Claude reviewer: Opus 5.5 at 20KB chunks.

Found all 7 known bugs on the gocql benchmark at $1.19/100KB and topped the calibration sample of the private Go project (0.74). Full scans cost $0.38–0.73/100KB with 0.81–0.97 precision after triage. Use it when you want a Claude-only pipeline or as the second opinion next to Codex.

Fable 5.2: strongest on small samples, most expensive at scale.

Best quality on the seastar and gocql calibration samples (0.65, 0.49), but $1.93/100KB on a full scan — four to seven times Codex or Opus. Worth it for a focused scan of a critical subsystem (--only), not for a whole large repo.

Sonnet 5.5: cheap but inconsistent. Haiku 5.5: don't use for review.

Sonnet ranged from 0.68 (private Go) to 0.09 (seastar C++) on calibration samples, and found 4 of 7 known gocql bugs. Haiku found 2 of 7, scored 0.00–0.32 and had rounds fail because reviewers left files unsubmitted.

For critical repos, run two models side by side.

Overlap between models is small: of the issues Codex and Fable found on gocql only 25 were found by both, on scylla-rust-driver only 12. start --profile codex-default,opus-default runs both on the same commit and plan; compare shows what only one found.

How to pick a chunk size

Let init calibrate it — and expect 20–40KB.

Review quality falls off sharply once a reviewer gets too much code at once. Across the calibration curves below, the best size was 20KB or 40KB in most runs, and every model lost a third or more of its quality past its knee (Fable on seastar: 0.78 at 40KB → 0.39 at 60KB). A few repos with large files tolerated 90KB (cpp-rs-driver, nodejs-rs-driver with Opus). Calibration costs $1–9 per model and is reused by every later scan.

Auto-triage

Agents re-check each finding against the checkout and mark it real, false positive, won't fix or unsure.

Method

  • All numbers come from local code-scan stores (~/.cache/code-scan) via npm run site (bin/site-export.js), which runs the tool's own scans, compare, init report and calibrate report on copies of the stores. Only counts, sizes, models and dollars are exported; private repositories are anonymized.
  • Price is list price of every token of every reviewer agent (preamble, coordination turns, re-reads), not just the code. Scans whose transcripts are gone show no price.
  • Precision counts only triaged findings. Most triage was done by Codex auto-triage, which may favour Codex findings.
  • Each comparison is one run; model sampling varies between runs.
